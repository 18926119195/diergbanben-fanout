## 1. 问题陈述

现有 RAG / 多轮拼接方案的常见失败模式：

1. **分析对象漂移**：模型在未声明的段落/文档上作答。  
2. **不可回溯**：无法回答「这条结论钉在书上哪一段、沿哪条推理方向产生」。  
3. **重复推演**：同一对象上已完成的方向被再次生成，产生漂移型幻觉。  
4. **软约束失效**：仅靠自然语言「请勿重复」无法在计算图上硬封锁注意范围。  
5. **无字领土失锚**：图标/扫描图区没有字符流时，系统无法锁定共同分析对象。  
6. **人机共指断裂**：人看见的画面与机器摄入的读值无法在同一位置上对照审计。

### 1.1 对比 RAG：两种「回溯」不可混同（V3.4 Informative · 强调）

RAG 与本规格的关键分叉，不只在「有没有检索」，而在 **回溯主锚放在哪一侧**：

| 回溯方式 | 在问什么 | 典型出现在 | 绑定性质 |
|---|---|---|---|
| **匹配回** | 生成文本 / 引用标签「像不像、对不对得上」某段语料 | RAG 答后 grounding、citation 对齐、attribution、靠模型自引出处 | **概率 / 软计算**，做不到百分百绑定 |
| **工程回溯** | 本轮选定≡注入的身份名单是谁，按身份显影效果 | 本规格：`premise_keys` → `key*` → AABB∥T | **注入侧确定性绑定** |

```text
RAG 常见产品路径：
  检索（策略，可用向量/同义）→ 生成 → 再把答案「匹配回」文档当出处
  ↑ 这一步「匹配回」= 概率回溯方式

本规格路径：
  检索（策略，不排斥向量）→ 选定 premise_keys ≡ 注入 Bundle
  → 生成（模型只吃自然语言效果 T）
  → 回溯只读注入名单显影（不猜答案措辞）
  ↑ 「工程回溯」= 确定性绑定「喂了谁」
```

**必须强调（防说重 / 防说满）：**

- 本对比 **不是** 断言「RAG / 前沿都没有 prompt 日志、从未记录塞进上下文的 chunk」。工程上可以记下「本次塞了 A,B」——那对「喂了谁」也可以确定。  
- 本对比 **是** 断言：当产品把 **「从生成侧匹配回语料」** 当作回溯主方式时，那种回溯是 **概率计算**；本规格说的工程回溯，指的是 **注入承诺上的确定性绑定**，不是匹配回。  
- 向量语义比较仍可用于 RAG/本规格的 **策略筛选**；同义问题留在策略层。身份层不靠同义反查。  
- 白名单引用 / 答后 grounding 可叠用为加强；**不能替代**选定≡注入，也不得冒充前提真回溯。

本规格给出一套 **以书本内禀位置锁（可哈希 `key*`）为唯一物理锚** 的前置控制协议，并定义如何将控制结果 **编译** 为进入主模型 Tokenizer / Attention 的硬输入。  
内禀坐标是**共指锁**：人经渲染还原物理真视觉，机器经读值取载荷；二者对齐靠 `key*`，不靠共享自然语言理解。  
对内（文献领土）`key*` 是动作铸造的位置坐标；对外不消灭 RAG 等自带坐标，而把策略执行编成可监督的绑定轨迹（见 §10.5）。

## 2. 术语（Normative）

### 2.1 内禀坐标（Intrinsic Coordinate）与位置锁 `key*`

**定义：** 标记「共同分析对象」的 **绝对锁死位置身份**，指向物理书本（或已解析文献）中的确定领土。  
实现上由 A 表**位置原子**承载；原子可有一张或两张脸（text / fig），但进房身份只有一把规范键。

**铸键本质（V3.4 Normative）：** `key*` **不是**由文本内容或框几何「算出来」的主键，而是由一次具备**时序唯一性**的**首次登记动作**（典型：页上第 `k` 刀排放）铸造。该动作一旦发生，必然连带当时的输入/输出效果（如提案 bbox → AABB、同条 content → T）。因此：

- **回溯的寻址对象** = 动作身份 `key*`（可哈希精确命中）；  
- **显影给人/机看的** = 该动作的效果（AABB ∥ T / fig 读值）；  
- 效果 **不是** 身份计算对象，只是动作的 payload。

```text
// 文字脸（流区间，左闭右开）
R_text ::= (doc_id, start, end) , kind = text
key*(R_text) = f"{doc_id}|{start}|{end}"

// 图脸（版面/图像领土；无字时的补充面孔）
R_fig  ::= (doc_id, fig_id, page, bbox?) , kind = fig
key*(R_fig)  = f"{doc_id}|fig|{fig_id}"

// 试点 OCR 槽门牌（排放动作铸键；与上式同属 A 表 key*）
key*_slot = f"{doc_id}|slot|p{page}|k{k}"

// 进房、闭包、回溯一律使用 key*（可哈希精确匹配）
```

**一锁两脸（Normative）：**

| 规则 ID | 规则 |
|---|---|
| IC-0 | **一个物理位置 ↔ 至多一个 `key*`**。text 与 fig 若共指同一领土，必须合并为同一 `key*`（两脸），禁止生成两个闭包。 |
| IC-1 | `R` / `key*` **只**表示书本/文献物理锚，**不**表示对话进度、时间轮次、拓扑视图或 `page_norm` 墨迹本身。 |
| IC-2 | 在同一 `doc_id` 且未重新跑解析管线 A 的前提下，同一位置原子的 `key*` **永不重算、不漂移**。 |
| IC-3 | 进入对话闭包、打包给主模型、回溯结论，均以 **`key*` 精确哈希** 为准。 |
| IC-4 | 「扩大/缩小」产生的是 **另一个精确 `key*'`**（仍来自 A 表项），不是修改旧锁的历史语义。 |
| IC-5 | **解绑/检索** 允许多种搜法（圈选几何、文字区间、fig id、`V_q` 候选）落到同一 `key*`；**进房禁止**「此键未命中则改查另一无关键」。 |
| IC-6 | `page_norm` / 强调笔多边形是**感官入口**，不是终局锚；必须经 A 表命中后才得到 `key*`。 |
| IC-7 | **动作铸键**：仅**首次登记动作**（排放/建表等）铸造新 `key*`；铸键瞬间写入效果（AABB、T/fig 等）。提问、推理、工具调用 **默认不造新键**，只**带上**已有 `key*`（可记入 ActionRecord / DirectionRecord）。 |
| IC-8 | **效果非身份**：AABB、T、fig 读值是动作效果；哈希与回溯寻址以 `key*` 为准，禁止以「字符串相等 / 事后用字找框」重算身份。 |
| IC-9 | **效果满意度路由**：后续策略行动须先判定对当前已铸键效果是否满意——满意 → 复用该键或与其它已有键组合；不满意 → **换绑**其它已有 `key*` 或组合 `member_keys`；仅当 A 表中**不存在**满意效果时，才允许触发新的首次登记动作以造新 `key*`。 |
| IC-10 | **组合 ≠ 造键**：多把已有键的效果需共置时，写入 `member_keys`（或 combo 索引）；**禁止**把表外拼接区间当成可搜主键（见 D10 / CL-1）。 |

**别名索引（Informative → 推荐实现）：**

```text
index_by_text_span: (doc_id, start, end) → key*
index_by_fig:       (doc_id, fig_id)     → key*
index_by_key:       key* → PlaceAtom
```

### 2.1.1 位置原子 `PlaceAtom`（A1 单元）

```text
PlaceAtom {
  key*: string              // 由首次登记动作铸造的身份
  doc_id, page
  bbox                      // 效果：page_norm，供圈选/人侧高亮
  faces: {                  // 效果：机器读值脸
    text?: { start, end, content }
    fig?:  { fig_id, image_ref? }
  }
  source: ocr | pdf_text | page_text | layout_fig | …
  minted_by?: action_id     // 可选：铸键动作 ID（时序唯一）
}
```

- **有字**：至少 text 脸。  
- **无字图/扫描区**：至少 fig 脸（补充面孔，不是第二个地方）。  
- 解析准全由上游负责；本规格要求原子可登记、可哈希、可审计。  
- **V3.4**：`bbox` / `faces` 是铸键动作的效果；换绑、组合、复用讨论的是「效果是否仍够用」，不是重算身份。

### 2.1.2 造键 / 带键 / 组合（速查）

| 动作类型 | 对 `key*` | 典型例子 |
|---|---|---|
| 首次登记（排放/建表） | **造新键** | 第 `p` 页第 `k` 刀切割登记 |
| 提问 / 推理 / 工具调用（效果满意） | **带上已有键** | Bundle 注入该槽 T；工具总结该槽 |
| 多效果需共置 | **组合** `member_keys` | 圈选连续多槽；多前提路径 |
| 对当前效果不满意 | **换绑**其它已有键或组合；仍无则 **新排放造新键** | V_q 改选候选；不满意则再切/再锚定 |

### 2.2 段落向量 `V_book`

A 管线为每个**位置原子**计算的 CPU 侧轻量 Embedding，与 `key*` 一一对应，供余弦检索。与主模型 Embedding **无关**。图脸可用图注/占位符/多模态描述的轻量向量（实现可选）。

### 2.3 意图向量 `V_q`（文中亦记 `V(提:当)` / `V_cur`）

对本轮用户提问文本的 CPU 侧轻量 Embedding。

### 2.4 对话闭包 `C`（通行证模型）

**定义：** 对话历史的**房子**（独立会话容器）。书级 `doc_id` 为父权限域（§5.0）。  
**`key*` 不是房号**：`key*` 是 A 表位置**秘钥（通行证）**；持有任一属于该房的秘钥，即可进入该房查看/续写方向资产。

```text
Closure C {
  closure_id: string          // 房号（独立于任何单一 key*）
  doc_id: string
  member_keys: key*[]         // 走过/成员秘钥（均须来自 A 表）
  primary_key?: key*          // 可选：当前激活读值所用的主秘钥
  directions: DirectionRecord[]
}
```

**索引（Normative）：**

```text
index_key_to_closures: key* → closure_id[]   // 这把秘钥走过哪些房
index_closure:         closure_id → C
```

| 规则 ID | 规则 |
|---|---|
| CL-1 | **通行证**：一把精确 `key*`（A 表项）可对应 **零个、一个或多个** 对话闭包；一间 `C` 可挂 **一把或多把** `member_keys`。禁止把「组合房」编码成表外假 `key*` 充当可搜主键。 |
| CL-2 | 闭包内资产按时间序堆积：**不同问法 / 不同推理方向**及其结论（结构穷尽方向，非穷尽模型参数）。 |
| CL-3 | 「新建闭包」= 新建带 `closure_id` 的房子，并把**当前已解绑的 A 侧 `key*`**（及可选的同轮确认成员键）写入 `member_keys`；**不**在 A 表发明新 `key*`。 |
| CL-4 | 走出闭包 = 离开当前房子 / 当前激活的共同分析上下文；不是离开「话题标签」的软概念。 |
| CL-5 | 提(当) / 圈选 **只**产出 A 表 `key*`；进房路由为 `key* → index_key_to_closures → 用户确认（或唯一命中）→ 激活 C`。若该秘钥尚无任何房，则按 CL-3 新建。 |
| CL-6 | 同一 `doc_id` 下允许并行多间 `C`；禁止用向量近似直接进房（进房仍须精确 `key*` 成员校验，见 EN-*）。 |

### 2.5 菜单指针记录（闭包内一条方向）

```text
DirectionRecord {
  direction_id,          // 闭包内稳定 ID（时间序即可）
  V_q,                   // 代表意图；可挂靠同义变体向量列表
  question_text,
  path,                  // 推理路径摘要（结构化或文本）
  conclusion,            // 结论
  premise_keys?: key*[], // V3.4：本条方向真正注入/挂靠的前提槽（可多键）
  created_at
}
```

> V3.4：既有实现中 `path` 常为字符串、ReasonEdge 偏双边单键；产品路径应逐步补齐 `premise_keys[]`，使人采纳/不采纳时可按键显影。

### 2.6 推理边 `ReasonEdge`（B1 产出，可选但推荐）

```text
ReasonEdge {
  from_R, to_R,
  relation: "overlap" | "disjoint",
  adjust?: "expand" | "shrink" | "same" | "partial",
  link_type: "incremental" | "refine" | "contrast" | "depend" | "explore" | "none",
  premise_conclusion?,   // 源闭包上选中的结论
  premise_path?,
  forbid_directions[]?   // 方向 ID 或短摘要
}
```

### 2.7 指令结构包 `InstructionBundle`

进入主模型 Tokenizer 之前的不可拆分结构体（见第 7 节）。

### 2.8 ActionRecord / tool-hook（V3.4 草案 · 宜升格）

在**工具调用 / 动作定义点**截获，把 I/O 挂到已有 `key*`（效果满意）或按 IC-9 换绑/造新键：

```text
ActionRecord {
  action_id: string
  action_kind: "emit" | "retrieve" | "infer" | "tool" | …
  premise_keys: key*[]     // 带上的已有键（注入监督名单）
  minted_keys?: key*[]     // 仅首次登记动作非空
  inputs_ref?:  …          // 可选：效果快照引用（非身份）
  outputs_ref?: …
  accepted?: boolean       // 人采纳/不采纳（路径级）
  created_at
}
```

| 规则 | 说明 |
|---|---|
| AR-1 | 截获点在 harness / 工具执行边界，**不**依赖主模型口述「我用了哪些前提」。 |
| AR-2 | `premise_keys` 必须 ⊆ A 表；白名单外键拒绝入库。 |
| AR-3 | 多候选推理路径 = 多条带 `premise_keys` 的记录；人裁采纳后写入闭包资产。 |

## 4. A 管线 / A1（书本侧，摘要）

**A1 定义：** 为物理文件建立 **可哈希的位置原子表**（旁路持久化，原件宜只读），使每个共同分析对象具备稳定 `key*`。

**时机（Normative）：** A1 在文件导入/解析完成时建立，**不依赖用户是否圈选**。圈选与 `V_q`（`V(提:当)`）锚定都只是在已建表上检索并锁定已有 `key*`；两脸亦在建表时挂到对应原子上，供后续比对与审计。

1. 调用上游解析（OCR / PDF 文字层 / 版面 figure）——**准全不由本规格担保**。  
2. 登记 `PlaceAtom`：text 脸和/或 fig 脸；共指则合并 `key*`。  
3. 可选：将 text 内容拼入逻辑流；fig 可写入占位符（如 `[FIG:…]`）以便统一编址。  
4. CPU 轻量 Embedding → `V_book`。  
5. 建立别名索引与 `index_by_key`。  

**感官解绑（圈选）：**

```text
page_norm 圈 ∩ 原子 bbox
  → 优先收成 text 命中的 key*
  → 若无字命中 → 收成 fig 命中的 key*（补充面孔）
  → 无任何命中 → 无锁，禁止调主模型
```

**非目标：** 主路径不依赖 LCS；跨格式对齐可作为可选预工序，失败则视为新文献。  
**非目标：** 本层不替代上游成为 SOTA OCR。

### 4.1 OCR 排放与坐标尺（Pilot 对齐 · Informative / 宜升格）

与 docuverse 试点一致的推荐实现：

| 规则 | 说明 |
|---|---|
| 同源 | 圈选/高亮所用页图与 layout/OCR 真源同一 `imageUrl`（对开页=一张图含左右两页，非两套 URL） |
| 排放原子 | 提案 bbox **先锁**为槽 AABB；T 优先取**同条提案** `content`；禁止主路径事后用 T 重绑 bbox |
| 坐标尺 | layout 返回页图像素时：`page_norm = 像素÷宽高×1000`；禁止将「数值≤1000」一律当作已千分格（矮图会系统性偏上） |
| 贴合 | layout 刀口松紧属上游质量；共位尺对齐 ≠ 框必须贴死字边 |
| 回溯前提 | 无稳定槽（AABB+T+`key*`）则不得声称「结论钉在书上哪一块」；高亮只读登记框（见 §10.0.1） |

## 5. B 侧主流程（Normative）

### 5.0 书域权限（Normative）

| 规则 ID | 规则 |
|---|---|
| SC-1 | 有效提问 **当且仅当**：会话已进入 `doc_id` 书域 **且** 已锁定该书内某个 `key*`。 |
| SC-2 | 跨 `doc_id` 默认 **拒绝**；须显式 `grant` 后才允许跨书 `ReasonEdge` / 再入。 |
| SC-3 | 无 `key*` → 不得调用主模型。 |

书级逻辑闭包 = 父权限域（`doc_id`）；子逻辑闭包 = 独立房子 `C`（经 A 侧 `key*` 通行证进入）。

### 5.1 总序

```text
用户提问 Q（须已满足 SC-1，或本步完成锚定）
  → Embed → V_q
  → 与 A 侧余弦 → 候选 key*（分析对象）          【对象锚定 · 只搜 A 表】
  → 用户确认精确 key*
  → index_key_to_closures(key*) → {C…}         【通行证查房】
       ├─ 唯一/用户选定已有 C → 激活
       └─ 无房 → CreateClosure(closure_id; member_keys⊇{key*})
  → 闭包内 V_q × {V_旧} 余弦                   【方向比对】
  → 用户审核分支（§5.3）
  → 若需生成：编译 InstructionBundle → 主模型
  → 回写 DirectionRecord
```

### 5.2 对象锚定与进房

| 规则 ID | 规则 |
|---|---|
| EN-1 | 进房所用通行证 **必须** 为 A 表精确 `key*`；**禁止**以区间重叠、向量近似、表外拼接键或「换一类键 OR」作为进房条件。 |
| EN-2 | 灰度书区：对 Top-K 候选由 **用户确认** 选定精确 `key*`。 |
| EN-3 | 以该 `key*` 查 `index_key_to_closures`：有候选房子则用户确认（或唯一命中）激活；无房则 `CreateClosure`（新 `closure_id`，`member_keys` 含该 `key*`）。**禁止**把「新建闭包」实现成「在 A 表新建 key*」。 |
| EN-4 | `doc_id` 必须进入 `key*`，以保证跨文档隔离。 |
| EN-5 | 系统应 **标记** 本次锚定命中的 `key*`、激活的 `closure_id` 及 `member_keys` 供审计；不得仅依赖模型自述出处。 |
| EN-6 | 若一间 `C` 需挂多把 A 键（组合读值），成员键必须逐个来自 A 表并写入 `member_keys`；Bundle 的读值载荷以用户确认的 `primary_key`（或当前锚定 `key*`）为准。 |

### 5.3 闭包内用户审核（方向层）

在当前激活的 `C` 内比对完成后（当前通行证为 `R*`）：

```text
                    ┌─ (1) 复用 ──────────────────────────── 停止
                    │     返回命中 DirectionRecord 的 path/conclusion
用户审核 ───────────┤
                    │     ┌─ (2.1) 留在该闭包
                    └─ (2) 不复用 ─┤     打包时写入负面清单 forbid_directions
                                  │     （同一房子；读值仍锚定当前 R* / primary_key）
                                  └─ (2.2) 离开该闭包
                                        进入 B1（§6）
```

| 规则 ID | 规则 |
|---|---|
| IN-1 | **复用** = 硬短路：不调用主模型。 |
| IN-2 | **留房不复用** = 仍在同一 `closure_id`；历史 DirectionRecord **保留**；本轮 Bundle 带 `forbid_directions`（软/硬执行见 §8）。 |
| IN-3 | **退房** = 唯一触发 B1 的入口；交叉/不交叉 **仅在退房后** 判定。（**Pilot：B1 UI 搁置，见 §6.0**） |
| IN-4 | 负面清单默认 **非永久删除**；永久隐藏为独立产品操作。 |
| IN-5 | **排除并继续推理（Pilot）**：用户将某近似方向加入 `forbid_directions` 后，应进入留房打包推理（Bundle 带该负面清单），不得停在「仅勾选、无下一步」。 |

### 5.4 设计意图（Informative）

- **内禀坐标**：确认共同分析对象是谁。  
- **闭包内多方向**：穷尽该对象上的不同问法 / 不同推理方向。  
- **退房 + B1**：处理对象迁移，以及对象间（或对象族内不同 `R`）的有向推理关系。

## 6. B1：出房后再入路由（Normative）

### 6.0 试点实现状态（2026-08-17 · Informative）

| 项 | 状态 |
|---|---|
| §6.1–§6.3 Normative 条文 | **有效**（厂商/自托管实现仍须遵守） |
| docuverse Reasoning Pilot UI / 状态机打磨 | **搁置**；不作为当前试点验收项 |
| 建议试点验收顺序 | 排放共位 → V_q 找槽 → 房内复用 / 排除+留房推理 →（日后再做）B1 |

**搁置期间草案（非正式）：** 退房后应展示 ≠ 当前 `key*` 的再入候选；`link_type` 下拉仅在「确认再入」时生效；单独改下拉不得换房。完整交互以试点文档 `docuverse/REASONING_PILOT.md` §4 为准，落地时再升格为 Normative 补丁。

### 6.1 触发与输入

**触发：** 用户选择 §5.3-(2.2)。

**输入：**

```text
V_q, Q, R_old, C_old（退房前激活的房子）, member 通行证含 R_old
```

此时 `C_old` 不再作为当前激活闭包。

### 6.2 步骤

#### B1.1 候选对象

`V_q` × A 侧 → Top-K 精确候选 `{R_1..R_K}`（均来自 A 表项）。

#### B1.2 相对 `R_old` 自动标注

对每个候选 `R_i`（区间运算约定全局固定）**立刻**打上关系标签（仅标注候选，不代替用户终裁）：

| 条件 | `relation` | `adjust` |
|---|---|---|
| `R_i == R_old` | overlap | same |
| `R_i ⊂ R_old` | overlap | shrink |
| `R_old ⊂ R_i` | overlap | expand |
| 相交且互不包含 | overlap | partial |
| 不相交 | disjoint | — |

**说明：** 进房前的对象锚定使用精确 `R*`；本表仅用于 **已退房之后**，描述「新候选相对旧对象」的几何关系。冷启动无 `R_old` 时不进入 B1，本表不适用。

#### B1.3 用户审核（必选）

用户确认唯一 `R_new` 及其 `relation`/`adjust`，并在需要时选定 `link_type`。  
若用户选择 `same`：应引导回 **留房+负面清单**，避免无效退房。

##### B1.3.1 `partial`（相交且互不包含）——跨闭包关系的脏入口（Normative）

`partial` **不是缺陷状态**，而是 **跨闭包关系** 的几何脏入口：

- 脏在：共同分析对象边界不清（算旧段延伸，还是另一段？）。  
- 清在：必须由用户 **显式指定** 要验证/建立的关系类型，禁止机器脑补。  
- 键与闭包：`R_i` 为另一精确 **A 表** 通行证 → 经 `index_key_to_closures` 进入 **另一间（或新建）** `C`，不是留在旧房；旧房与新房之间只保留用户确认的 `ReasonEdge`。

**产品语义：** 用户认为闭包 A 与闭包 B 可能存在某种关系，希望模型去 **验证、对比、依赖推导或发现新规律**——而非默认「B 是 A 的 expand，把 A 的结论强行搬过去」。

| 做法 | 含义 | 允许？ |
|---|---|---|
| 自动当 `expand` 并强继承旧结论 | 半截重叠时结论乱贴到另一半 | **禁止** |
| 用户显式选边：`contrast` / `depend` / `explore` | 跨闭包有指向的推理（验证/依赖/探索发现） | **允许** |
| `link_type=none` | 只换对象，不做关系断言、不继承前提 | **允许（安全默认之一）** |
| 用户显式选 `refine` / `incremental` | 人认定应按精炼或增量继承 | **允许（须明示，禁止自动）** |

#### B1.4 精确再入

```text
确认 R_new（A 表 key*）
  → index_key_to_closures(R_new)
       ├─ 激活用户选定的已有 C
       └─ 无房 → CreateClosure(closure_id; member_keys⊇{R_new})
```

仍 **禁止重叠进房**；仍 **禁止**表外拼接键当通行证。

#### B1.5 写出 ReasonEdge 并交接

```text
ReasonEdge {
  from_R: R_old,
  to_R: R_new,
  relation, adjust,
  link_type: 由产品映射（下列为默认策略，partial/disjoint 禁止隐式强继承）
    overlap+expand   → incremental
    overlap+shrink   → refine
    overlap+same     → 不应到达 B1（回留房）
    overlap+partial  → 禁止自动；必须用户三选一骨架：
                         refine | incremental | none
                       若意图为跨闭包验证/发现，用户改选：
                         contrast | depend | explore
    disjoint         → 默认 none；仅当用户显式选择
                         contrast | depend | explore 才写入非 none
  premise_*: 仅当 link_type ∈ {incremental, refine, depend} 等允许继承的类型时写入；
             contrast/explore/none 默认不带强前提结论（explore 可带「待验证假设」字段，另议）
}
```

| 规则 ID | 规则 |
|---|---|
| B1-1 | `disjoint` 默认 `link_type=none`，**禁止**隐式继承旧结论（防跨段/跨文档幻觉通道）。 |
| B1-2 | 非 `none` 的边必须进入 InstructionBundle。 |
| B1-3 | B1 不删除 `C_old` 历史。 |
| B1-4 | `partial` **禁止**自动写入强继承边（禁止未审即 `expand`/`incremental`）；必须用户显式选择 `refine` / `incremental` / `none`，或跨闭包向的 `contrast` / `depend` / `explore`，再进入 Bundle。 |
| B1-5 | `partial` 表示跨闭包几何脏入口：再入的是 **另一间** `C`（经 `R_new` 通行证进入），与旧房为不同 `closure_id`；关系只存在于用户确认的 `ReasonEdge` 上。 |

交接后：在新激活的 `C` 内执行与 §5.3 相同的方向决策；空闭包可直接打包。

### 6.3 B1 的控制论意义（Informative）

B1 不仅是换房，更是在 **`R` 与 `R'` 之间建立有类型推理边**，形成指向性控制：

- 对象内穷尽：闭包内 DirectionRecord 时间序。  
- 对象间（及对象族内不同坐标）定向：ReasonEdge。  
- **`partial`**：跨闭包关系的脏入口——几何不清，故禁止自动强继承；由用户指定 `contrast` / `depend` / `explore`（验证或发现规律）或显式 `refine` / `incremental` / `none`。

## 7. InstructionBundle（进入 Tokenizer 的契约）

### 7.1 字段（Normative）

```text
InstructionBundle {
  // 分析对象（当前读值通行证；须 ∈ member_keys，且来自 A 表）
  R: IntrinsicCoordinate,          // kind=text|fig
  source_excerpt: string,          // 机器读值：原文或图读值说明，必须非空
  // 可选 human_view_ref（页/bbox）供 UI 审计，默认不进模型

  // 闭包与方向（通行证模型）
  closure_id: string,              // 当前房子（≠ 任意单一 key*）
  member_keys: key*[],             // 本房通行证集合（均来自 A 表）
  // 兼容：旧字段 closure_key 若保留，语义仅为 R.key，不得当作房号
  V_q: vector,
  question: string,

  // 复用短路不生成 Bundle；以下为需生成时
  forbid_directions: [             // 留房不复用
    { direction_id, question_summary, conclusion_summary }
  ],

  // B1 再入时
  edge?: ReasonEdge,

  // 增量前提（仅当 edge.link_type != none 或深化类产品动作）
  premise?: { conclusion, path_summary, from_R },

  // 策略
  policy: {
    must_ground_to_excerpt: true,
    disallow_outside_R: true
  }
}
```

### 7.2 Token 布局建议（Informative → 可升格为厂商规范）

推荐分段，便于 Mask 编译：

```text
[SEG_SYSTEM]     角色与硬规则
[SEG_OBJECT]     source_excerpt（仅当前 R）
[SEG_PREMISE]    premise.conclusion / path（若有）
[SEG_FORBID]     forbid_directions 摘要（若有）
[SEG_EDGE]       ReasonEdge 说明（若有）
[SEG_QUERY]      question
[SEG_OUTPUT]     （生成区）
```

## 8. 厂商侧：Attention Mask / 可见性编译（Normative for hard control）

### 8.1 能力分级

| 级别 | 能力 | 幻觉/越权控制硬度 |
|---|---|---|
| L0 | 仅文本 Bundle，无 Mask | 软约束 |
| L1 | 结构化分段 + logits 约束（如强制引用） | 中 |
| L2 | **自定义 Attention Mask / 分段可见性** | 硬（本规格目标） |

应用层已解决「对象与方向图」；**参数级/计算图级封锁**依赖 L2。

### 8.2 Mask 编译规则（建议作为 Serving API）

输入：`InstructionBundle` + 分段 token 偏移表。  
输出：布尔矩阵或分段可见性描述 `MaskSpec`。

| 规则 ID | 规则 |
|---|---|
| M-1 | `[SEG_OUTPUT]` 对 `[SEG_OBJECT]`：**允许**注意。 |
| M-2 | `[SEG_OUTPUT]` 对非当前 `R` 的文献原文：**禁止**（若误入序列）。 |
| M-3 | 若存在 `premise`：允许注意 `[SEG_PREMISE]`；**禁止**把旧方向的完整推演过程再放入可注意区（旧过程默认不进序列）。 |
| M-4 | `[SEG_FORBID]`：允许模型「读到禁令」；解码策略上应抑制复述 forbid 中的结论作为新答案主干（可用拒绝采样/分类头辅助）。 |
| M-5 | `link_type=none`：禁止注入跨 `R` 的 premise。 |
| M-6 | `disjoint|partial` 且 `contrast|depend|explore`：仅按边开放 `from_R` 的 **结论句或假设句**，默认不开 `from_R` 全文；`partial` 未带用户显式 `link_type` 时 **拒绝编译** Bundle。 |

### 8.3 API 草图（厂商实现参考）

```text
POST /v1/responses
{
  "model": "...",
  "bundle": { ... InstructionBundle ... },
  "enforce": {
    "attention_mask": "compile_from_bundle_v1",
    "grounding": "excerpt_only"
  }
}
```

若无法提供 Mask：返回明确能力协商 `enforce.attention_mask=unsupported`，客户端降级为 L0/L1，**不得静默假装硬执行**。

### 8.4 表述约束（对外与对内）

允许：

- 结构穷尽同一分析对象上的问法与方向；  
- 有向推理边控制；  
- 在 L2 下硬限制注意范围，抑制跨段/跨文档越权。  

禁止承诺：

- 「穷尽模型全部参数」；  
- 「零幻觉」；  
- 在不提供 Mask 的托管 API 上宣称已硬封锁注意。

## 9. 回写管线 C（摘要）

1. 主模型返回后、UI 展示前，CPU 校验非空/非拒答等。  
2. 写入当前激活 `C`（`closure_id`）的新 `DirectionRecord`（`V_q`, path, conclusion）；并确保本轮通行证 `R.key` ∈ `member_keys`。  
3. 失败策略：允许展示但不入库 / 或阻塞——产品二选一，须配置化。

无 C 则闭包无法积累方向资产，复用率趋零。

## 10. 回溯、审计与抗幻觉性质（Informative）

### 10.0 同锁双通道审计（推荐产品能力）

```text
点 key*
  ├─ 人：渲染物理真视觉（页图 + bbox 高亮）
  └─ 机：展示该锁上的 text/fig 读值
       → 对照出入（多字/少字/框偏/无字有图等）
```

解析不准显示为 **读值与原件出入**；本层职责是暴露，不是承诺消灭。

### 10.0.1 槽 → 回溯（2026-08-17 试点已验证思路 · Informative）

**先有槽，才有真回溯。** 槽 = A1 排放原子（`key*` + 登记 AABB + 读值 T/fig），不是答完再反查字符串的 citation 贴纸。

```text
排放切刀 → 登记槽（框先验锁定；T 填同条）
  → 提问 / V_q 只在已建槽上找门牌
  → 进房、打包、方向结论挂 key*
  → 回溯：conclusion → key* → 页图绿框(只读登记 AABB) ∥ 机器读值
```

| 主张 | 说明 |
|---|---|
| 弄槽 | 物理领土先有稳定身份证；否则「钉在哪一段」无解 |
| 回溯 | 人侧高亮 = 登记框，禁止主路径用字重绑破坏共指 |
| 共指 | 人看真视觉、机看读值；对齐靠 `key*`，不靠共享 NLP 理解 |
| 与 grounding 差 | **见 §1.1**：RAG 常把「答后匹配回」当回溯（概率）；本规格以选定≡注入的工程回溯为权威，再按 `key*` 显影同一槽 |

Pilot 侧坐标尺（像素→`page_norm`）与同源页图共位，见 `docuverse/REASONING_PILOT.md` §0–§1；贴合松紧属上游 layout，不属控制层必过项。

### 10.1 回溯

任意结论应可追溯：

```text
doc_id + key*（通行证）
  → index_key_to_closures → closure_id
  → direction_id → path/conclusion / premise_keys?
  →（感官）PlaceAtom.bbox 绿框高亮原页
可选：ReasonEdge 链（房与房）
```

### 10.2 可抑制的幻觉类型

- 跨段 / 跨文档串台（精确键 + Mask M-2/M-5 + SC-2）。  
- 同对象重复乱推（复用短路 + forbid）。  
- 无锚生成（无 `key*` 不调用主模型）。  

### 10.3 不可由本规格单独消灭的幻觉

- 正确 `key*` 上的首次生成错误；  
- A 侧错锚（需 Top-K + 用户确认）；  
- L0 下模型忽略文本禁令；  
- 上游 OCR/版面错误（属解析质量，非控制层）。  

### 10.4 对主推理模型的当前能力边界（V3.4 Normative 声明）

**必须对外写明，避免过度承诺：**

| 已做到 | 尚未做到 |
|---|---|
| 监督并登记 **送进主模型的注入集**（Bundle 中的 `R` / `member_keys` / 读值 T） | 钉住生成过程中 **推理行动最临近的注意力位点**（实际盯了哪些 token / 哪一口槽） |
| 按 `key*` 哈希显影：绿框 ∥ 读值（荧光剂打在**注入名单**上） | Serving 级 Attention Mask / 注意力探针下的「路过哪」显微镜（L2，见 §8） |

```text
因此：注入集可工程回溯 ≠ 模型内部临近推理位点已完全可见。
偏差来源：当前工作环境与条件（托管 API、无强制 Mask、缺注意力日志等），
         而非「动作铸键 / 槽登记」概念错误。
对主模型的影响目前仍有限：管住「送什么」，尚未管住「想的时候最近用了啥」。
```

想对不对（结论对错）仍归推理模型；本层拆开的是「喂错了 vs 想错了」。

### 10.4.1 选定 ≡ 注入（V3.4 Normative）

```text
选定 premise_keys = [k1…kn]
  ⟺
本轮 Bundle 对象载荷恰好来自这些键的效果（T/fig…）
  且元数据名单与载荷同一事务提交、一一对应
```

| 允许 | 禁止 |
|---|---|
| `ki → 查表取效果 → 原样写入 SEG_OBJECT` | 选定 A，实际塞进 B |
| 少选少喂、多选多喂 | 名单一套、上下文另一套 |
| 变换对象时同步改名单 | 选定后静默改写/丢段却不改 `premise_keys` |

**回溯主路径：** 读注入名单 → 按 `key*` 显影 AABB∥T；**禁止**把「解析生成措辞 / 同义反查文档」当作权威前提回溯。

### 10.4.2 不断缩窄：用工程逼近「实际用了谁」（V3.4 Informative）

注入集证明的是「喂进去的是谁」（可用集合的**上界**），不是注意力最临近位点。可用工程把前者**逼近**后者，但性质必须说准：

```text
注入集很大     → 只知「可能用过这里面」
不断缩窄注入集 → 「可能集合」变小
缩到极少/单槽 → 「喂进去的」与「能用来想的」上界重合更紧
```

| 断言 | 是否成立 |
|---|---|
| 检索→精排→断崖锁/人裁→少喂，值得做 | ✅ 克制高效 |
| 缩窄 = 收紧「最多能用谁」的上界 | ✅ |
| 缩窄后已等于 token 级「生成时最近盯了谁」 | ❌ 仍不是注意力显微镜（需 L2） |

单槽喂入时：名单 ≈ 唯一可用前提，实务上常够用。多槽喂入时：名单仍是上界；若需更细，可叠白名单勾选或 L2，但不得取消选定≡注入。

### 10.4.3 与强制引用白名单 / attribution / RAG「匹配回」的切割（V3.4 Informative）

**核心对比（与 §1.1 同构，此处钉审计语义）：** 批评的是 **回溯方式**，不是「别人有没有写过日志」。

| 回溯方式 | 在问什么 | 绑定性质 |
|---|---|---|
| **匹配回**（RAG 答后 grounding、citation 对齐、attribution、模型自引） | 生成侧「像不像 / 引得对不对」 | **概率 / 软**，非百分百绑定 |
| **工程回溯**（本规格） | 注入侧「选定≡注入的是谁」→ 按 `key*` 显影 | **确定性**绑定「喂了谁」 |

| | 强制引用白名单 / 受限生成 | Attribution / 答后 grounding | 本规格主路径 |
|---|---|---|---|
| 权威「用了谁」 | 常信模型是否按白名单引用成功 | 信答后相似/贡献分数 | 信 **选定≡注入的 `premise_keys`** |
| 性质 | 生成侧纪律（加强项） | 生成后 **匹配回**（概率近似） | 注入侧承诺（工程回溯） |
| 失败模式 | 引用对了标签、吃错上下文；或上下文对了、引用乱写 | 同义改写导致「像谁」漂移 | 若违反选定≡注入则审计作废 |

```text
白名单引用：可叠用 —— 加强，不能替代选定≡注入。
RAG/attribution「匹配回」：从答案侧做概率对齐，不是工程回溯。
即便系统另有「本次 prompt 塞了 chunk A,B」的日志：
  那是注入痕迹；若产品仍以「匹配回」为回溯主锚，对外叙事仍是概率回溯方式。
本规格：权威锚必须在注入承诺；按动作铸造的 key* 显影登记效果。
```

**说白了：**  
RAG 等常见把 **概率匹配回** 当作「回溯」；本规格说的 **工程回溯** 是注入侧确定性绑定。  
二者可并存于同一流水线，但 **权威锚只能选工程回溯**；匹配回不得冒充前提真回溯。

### 10.5 策略层 vs 监督层（V3.4 Informative）

```text
策略层：决定送哪些槽 / 如何检索 / 是否扩上下文 / 通用 harness 的工具环
监督层：策略一旦执行，注入的 key* 名单可登记、可显影、可被人采纳或拒绝
```

- 准且高效 = **策略问题**（可自动选槽；人确认可选）。  
- 可追踪 = **监督问题**（本规格已立住的核心）。  
- 通用 agent harness（工具环、沙箱、编排）偏策略执行；本规格偏 **前提轨迹监督**，宜互补，不声称全面更强。  
- 轨迹是优化原材料；**不声称**已有「自动优化一切策略」的引擎。

### 10.6 产品优先级（V3.4 Informative；不废止 EN/SC）

强调：Agent 可生成多条可能路径，每条带 `premise_keys[]`，人采纳/不采纳。  
选槽可自动化；荧光剂成立条件是工程记下实际注入的 `key*`，不是必须人手点槽。  
§5 SC/EN **Normative 条文保留**（精确键注入与书域隔离）；产品灰度可用断崖自动锁，但不得取消注入登记。

## 附录 A｜与错误定义的切割（Informative）

下列概念 **不得** 再称为「内禀坐标」：

- 对话时间进度 / 轮次；  
- 可重画的拓扑视图坐标 / **未吸附的 `page_norm` 墨迹框**；  
- 与书本锚混名的「动态内禀」；  
- 向量近邻「语义相似段」（可作找锁候选，不可当 `key*`）；  
- **文本字符串或框几何本身**（它们是铸键动作的**效果**，不是身份）。  

对话闭包是 **独立房子**（`closure_id`）；`key*` 是进入房子的 **A 表通行证**，不是房号本身。  
一把通行证可走过多间房；一间房可挂多把通行证（`member_keys`）。  
figure 是无字时的**补充面孔**，不是第二个地方。  
**V3.4：** `key*` 由时序唯一的首次登记动作铸造；后续策略行动带键 / 换绑 / 组合，不把每次工具调用都当成造键。
