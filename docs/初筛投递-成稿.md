## 二、正文全文（对方回复后发送，约 950 字）

### 1. 一句话成果

我完成的研究成果，是把 **外参考性坐标**（chunk 编号、答后匹配回、生成侧 citation）与 **内禀坐标**（由首次登记动作铸造的可审计对象身份）做成可运行的范式叠合：  
在不排斥、可叠合现有 RAG 的前提下，把「这轮主模型到底依据哪条前提」收成 **选定≡注入** 的确定性回溯，并在文献页上以 **人机两脸** 显影——人看物理框，机读同锁机器读值，对齐靠身份而非「双方都懂这段话」。

**说明：** [演示说明]

### 2. 问题从哪来（跨学科起源 · 短）

问题起点不是「再包一层 RAG」，而是人机协同里缺一层 **可审计的前提监督**：

- 符号生产关心：标记如何 **稳定指称** 分析对象；
- 交互动力关心：人如何在对象上 **持续行动并感到可把握**。

二者合到工程上，就是：分析对象要有稳定身份；人与模型看到的是同一把锁上的不同「脸」；策略（检索、扩写、重排）可以换，但 **「送进模型的到底是谁」** 必须可对账。  
由此落到：**动作登记 → 效果（框 ∥ 读值）→ 注入名单 → 按身份回溯**，而不是答完再用相似度猜出处。

---

### 3. 范式对比

| | 外参考坐标（常见 RAG / 引用） | 内禀坐标（本成果） |
|---|---|---|
| 身份 | 切块编号、临时引用、语料偏移 | 首次登记动作铸造的稳定对象身份 |
| 回溯主方式 | 生成后再 **匹配回** 文档（相似 / 自引 / citation） | **选定≡注入** 名单 → 按身份显影 |
| 绑定性质 | 软 / 概率 | 注入侧 **确定性**（监督「喂了谁」） |
| 与 RAG 关系 | RAG 主路径之一 | **叠合**：RAG 做候选；内禀做监督 |

**关键澄清（对照实验设计）：**  
演示里 **不是** A、B 两路各喂不同段落。流程是：**检索候选 → 测试员选定一条 → 主模型只吃这一条 → 答完后分两种回溯 UI**——控制变量是 **出处机制**，不是输入差异。

| 对照项 | 含义 |
|---|---|
| **进模型输入（共用）** | 测试员选定的那一条段落（对照基准） |
| **回溯 A · 参考来源** | 推理前检索 Top 列表 + 模型末尾写的 `依据:#n`（NotebookLM 式软引用） |
| **回溯 B · 进模型回执** | 推理前冻结的注入段落，按身份钉回页上绿框 |

故意选 **非检索 #1** 的段落，更容易看出：A 常仍指向 Top 或乱写序号，而 B 能钉回你选定的那条——差异不在「会不会检索」，在 **回溯主锚是概率匹配还是注入承诺**。

---

### 4. 已验证路径（录屏可见）

1. 上传 PDF → 页切割登记 → 每段有稳定槽位与页上框  
2. 提问 → 向量检索 + 意图扩展得候选列表  
3. **测试员选定一条** → 写入推理 Bundle（中间零纰漏）→ 调用主模型 **一次**  
4. 答毕：**进模型依据** / **回溯 A** / **回溯 B** 三路回跳页上绿框  
5. 回溯不靠猜答案措辞，靠 **注入名单与登记几何**

**技术栈（试点）：** React + Vite 前端；向量检索（Qwen Embedding）；DeepSeek 类主模型；智谱 OCR/layout 代理。  
**边界（诚实）：** 当前监督的是 **Bundle 注入集**，尚未做到推理时最临近注意力位点；复用短路、forbid、Agent 工具挂 premise 等为规格方向，产品环部分进行中。

---

### 5. 对教育 / 教研场景的可见收益

- **出处可钉：** 对学生、教研讨论可展示「依据的是页上哪一段」，而非事后相似匹配  
- **可评价：** RAG 效果可对照「检索命中」与「注入对账」两层指标  
- **可追责：** 分清楚是「喂错前提」还是「模型想错」  
- **交互语义：** 批注、提问、翻页挂在同一分析对象上连续发生——不必每次对话另开漂浮窗口（愿景已试点槽上挂问与回溯）

**可审计性** 是我与常规「检索 + 生成 + 答后 grounding」的核心差异化，不是比绿框 UI，而是比 **回溯主锚是否确定**。

### 6. 展望（标清已验 / 进行中 / 未来）

**已验证地基：** 选定≡注入对账、页上两脸共位、同输入 A/B 回溯对照、策略层可插 RAG。

【0:00】这是 DOCUMVERSE 文献对照试点。左边是 PDF 页，右边是出处对照台。

【0:15】我先上传教材 PDF，等索引就绪。

【0:30】输入问题，点「查找相关段落」——这里走向量检索，也可以叠意图扩展。

【0:45】系统返回 Top 5。演示时我故意不选 #1，选一条匹配度更低的——
        这样后面更容易看出「软引用」和「注入回执」的差别。

【1:00】点「开始推理」。注意：主模型只吃我选定这一条，只调用一次。

【1:20】模型回答出来了。看三路对照：
        第一，进模型依据——当时喂入的就是我选的那条；
        第二，回溯 A——检索列表里模型写的「依据:#n」，常常还对不上我选的；
        第三，回溯 B——注入回执，点回去绿框钉在我选定的登记框上。

【1:50】点 A 和 B，页面上绿框会跳。A 可能落在检索 Top，B 一定落在我选定对象。
        同一输入、同一次推理，差别只在回溯机制：概率匹配 vs 注入承诺。

【2:15】这不是比「有没有绿框」，而是比教育场景里出处能不能对账、能不能展示给学生看。

【2:30】检索仍可接更强的 RAG；我补的是注入侧监督层。谢谢。

## 四、附件 / 追问应对（备用短答）

**Q：和 NotebookLM 有什么区别？**  
A：NotebookLM 是 Top-K 进 context + 生成 citation，回溯仍偏软。我这里对照实验先 **锁死同一条进模型**，单独看 citation 式回溯 vs 注入回执谁更可靠；产品形态上两者可叠合，不是二选一。

**Q：源码能看吗？**  
A：初筛以录屏对照为主；键公式与排放细节涉及研究资产，深聊可签 NDA 后本地演示或有限度代码走读。

**Q：有没有线上 Demo？**  
A：当前以录屏为主，避免前端 bundle 泄露内禀坐标工程细节；若需要可约限时口令演示。

**Q：算 AGI 吗？**  
A：目标是进生产的人机系统：AI 应知道动作发生在哪、效果是什么；效果不佳则换绑并避免重复无效路径——这是交互与审计问题，不是口号。
