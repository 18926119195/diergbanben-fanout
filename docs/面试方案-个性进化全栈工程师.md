## 2. 研究历程（投递叙事主线 · 研究成果简述核心）

> **写法提示：** 本节是投递文 / 一页纸 / 录屏旁白的主骨架，目标是把「问题→范式→已验证效果」写清楚。  
> **篇幅：** 书面约 500～800 字，或配 2～3 分钟对照录屏即可；不必按「现场口述 5～7 分钟」理解。  
> **若获邀面试：** 可原样收成口试要点，仍建议以 A/B 演示为主、实现细节留到深聊。

### 2.1 问题从哪来（核心目的先钉）

**核心目的：人机交互系统**——不是「再做一个更强的检索」，而是希望人与模型在共同分析对象上协作时：

1. **可审计：** 知道前提是谁、能否钉回对象；  
2. **可复用：** 同对象同方向不必反复烧主模型；  
3. **可优化：** 轨迹可评价、可排除、可再展开。

主流 RAG/Agent 多在提 **策略**（找谁、扩上下文）。  
缺的是策略执行后，人机双方能否稳定握住「用的是哪个对象」——否则交互漂、审计只能靠答后概率匹配回。

跨学科起源（点到为止）：符号生产力关心稳定指称；心理动力关心人在对象上持续行动的可把握感 → 落成「身份可锁、两脸共指」的人机协同。

### 2.2 范式更迭：外参坐标 × 内禀坐标（对外版 · 少实现细节）


|          | 外参 / 外参考性坐标（常见）       | 内禀坐标（本成果 · 对外表述）        |
| -------- | --------------------- | ------------------------- |
| 身份       | 切块编号、临时引用、答后对齐        | **对象级物理锚定身份**（由登记动作给出，稳定可哈希） |
| 回溯怎么做    | 答案 ↔ 语料 **匹配回**（软/概率） | **注入承诺** → 按身份显影（确定）    |
| 和 RAG 关系 | RAG 本身                | **不排斥**；RAG 策略插头 + 内禀监督  |


**叠合，不是取代：**  
RAG 负责「候选可能是谁」；内禀层负责「选定之后送进模型的是谁」。

> 初筛文案可用「物理锚定 / 注入承诺」；**「第 k 刀 / 键公式」留到签 NDA 或技术深聊后。**

### 2.3 已验证：用项目 A/B 对比展示（推荐主演示）

**不要**在初筛细写「怎么铸出来」。  
**要**准备已有超文本/文献项目，做 **同一输入量** 对照（录屏或限时演示链接）：

| 路 | 做法 | 观众应看到 |
|---|---|---|
| **A · 无本层（或仅常规 RAG 叙事）** | 同样问题 → 生成 → 靠引用/相似「匹配回」 | 出处可能漂、同义难钉、难对账 |
| **B · 有本层** | 同样问题 → 注入侧锁定对象 → 回溯 | 页上框∥读值钉住；名单可对账 |

**推荐演示顺序（录屏 2～3 分钟）：**

1. 打开项目链接（超文本/页浏览界面）  
2. **同一句用户输入** 走 A，展示「匹配回」的含糊/漂移  
3. **同一句输入** 走 B，展示两脸显影与注入名单  
4. 一句话收束：差异不在「会不会检索」，在 **回溯主锚是概率匹配还是注入承诺**

**懂行的人是否「一看就懂物理锚定」？**  
概念上懂，但 **A/B 对比仍然值得做**：  
- 给不懂行的 HR/业务看效果；  
- 给懂行的人证明你不是口头概念，而是 **可运行对照**。  
结论：**对比演示比细讲实现更重要；不是「根本不需要」。**

对外成果表（效果导向，非实现导向）：

| 观众能感知的效果 | 状态 |
|---|---|
| 同输入下，回溯从「猜」变成「钉」 | ✅ 用 A/B 证明 |
| 人看页、机看读值，同一对象 | ✅ 共位可演示 |
| 可接/可叠现有 RAG | ✅ 架构主张 |
| 为复用/排除/优化留接口 | ✅ 规格方向；产品环可承认未完 |

## 3. 展望（分层写 · 标清「已验 / 未做」）

### 3.1 展望一：对可审计 AI / 超长上下文 / RAG —— **可行且已局部验证**


| 方向     | 说法                    | 边界                                     |
| ------ | --------------------- | -------------------------------------- |
| 可审计 AI | 注入侧确定性回溯 = 审计地基       | 已验证的是「喂了谁」，不是注意力掩码                     |
| 超长上下文  | 用身份复用/排除，避免整段上下文无结构堆积 | 「有效注意力范围内的拓扑结构如何呈现」= **未来深挖**，诚实说现在不做满 |
| RAG    | 接最强检索 + 内禀监督 = 差异化    | 不说「取代 RAG」                             |


### 3.2 展望二：任意分析对象的操作语义（产品愿景 · 教育场景极贴）

> 看书/翻页时，不必开一堆对话窗口。  
> 批注、提问、输入，都钉在**当前页上的分析对象**上；  
> 送进模型的前提以 **两张脸** 呈现，并可回溯「推理所依据的前提是谁」。  
> 整条推理路径如何在 UI 里展开（注意力有效范围内的拓扑结构），是下一层交互问题——**可做，但不是本轮已交付。**

投递落点：这是 **交互语义 / 轻量「内容操作系统」**，和贵司「输入→AI→输出」全链路、前端流式交互同族。

### 3.3 展望三：若能对接大模型厂商

用同一套内禀锁定，更接近「真正进推理的上下文」：

- **复用** 已有路径 → 省算力 / 省调用（对 JD「成本」）  
- **排除** 已走过方向 → 收紧有效注意范围，展开新可能  
- **人机校验** 候选路径 → 采纳/不采纳 → 自我迭代的生产环

已有钩子：复用短路、forbid、DirectionRecord、ActionRecord 草案。  
未完成：厂商 Mask/注意力探针、完整多路径 UI。

### 3.4 超文本上下文 · 前端渲染与语义是否解耦？

已成形：不是一串无结构聊天，而是 **挂在分析对象身份上的路径记录网**（超文本上下文）。  
路径「怎么画成漂亮拓扑」可单独立项；先要诚实判断解耦做到哪一步。

**判断：主路径上「身份语义」与「页上渲染」已解耦；还不是完整「任意 UI 皮肤无关」的操作系统级解耦。**

| 层 | 谁负责 | 是否与另一层绑死 |
|---|---|---|
| 身份语义 | 稳定对象身份 + 注入名单 + 读值效果 | 不依赖绿框怎么画、不依赖用字重绑框 |
| 页上渲染 | 登记几何在页图上高亮（人脸） | 高亮只读登记框，**禁止**主路径用文本反推框（代码/规格已钉） |
| 策略检索 | 向量/RAG 可换 | 不改写身份层 |

因此投递/初筛可写：

> 前端渲染（人怎么看见框）和对象语义（系统认定「是谁」、模型吃什么）是分开的：  
> 换皮或改交互，不应靠「再匹配一遍字」重算身份；身份在登记与注入承诺里。

**尚未等于：** 任意前端框架即插即用、推理路径拓扑可视化已完成、与厂商注意力层解耦。  
路径可视化 = 交互语义下一跳；**点明解耦主张即可，勿写「操作系统已做完」。**

### 3.5 使命与 AGI（可选 · 初筛一句，文化面可展开）

> AI 应知道动作发生在哪、效果是什么；效果不佳则换动作并避开旧效果。  
> 前面的产品介绍，是我约三年脱产跨学科研究的成果之一。  
> 核心动力：在 AI 加持下做出更好的 **生产界面**，面对社会、环境、精神三重不确定时  
> 仍能激发协作与创造力——把人最大程度团结在可把握的共同对象上。这是使命，不只是功能点。

**纪律：** 使命感人，初筛仍以 A/B 演示为钩子；使命放在「为何坚持」或结尾一句，勿冲掉工程证据。
